## 5. Version Upgrade Rules (v1 → v2.2)

When upgrading from v1:
- Preserve existing intent unless explicitly contradicted by spec
- Remove ambiguous or implicit behavior
- Replace ad-hoc logic with state-guarded logic
- Introduce idempotency where missing
- Add TTL and recovery where processes may hang
- Treat AI quota exhaustion as a **normal, recoverable state**

DO NOT:
- rewrite the system from scratch
- introduce new states
- silently change API behavior
- auto-retry AI calls aggressively

## 6. Absolute Constraints (MUST / MUST NOT)

### MUST:
- Enforce the official state machine
- Reject illegal state transitions
- Ensure only one summary job per meeting
- Ensure final summary is fetched via REST only
- Close SSE connections deterministically
- Make resume-summary idempotent and single-flight
- Respect concurrency limits

### MUST NOT:
- Add new states (PAUSED, ERROR, etc.)
- Persist partial summaries or transcripts
- Use SSE as a data source of record
- Auto-resume AI jobs when quota returns
- Introduce WebSocket or alternative protocols
- Assume AI calls always succeed
